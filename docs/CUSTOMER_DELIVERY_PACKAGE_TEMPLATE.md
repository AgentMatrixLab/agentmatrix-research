# 因子库客户交付包标准模板

适用对象：A 股因子库、因子数据服务、因子研究平台、因子 API 产品的正式客户交付。

使用原则：
- 客户拿到后，应能判断“交付了什么、怎么部署、怎么验收、出了问题找谁”。
- 所有“未交付”“规划中”“需客户另备环境”的内容必须单独标注。
- 不允许把研发仓库直接当交付包；必须整理为客户可读的结构化交付目录。

---

## 一、推荐交付目录

```text
customer_delivery_package/
├─ 01_商务法务/
├─ 02_交付范围清单/
├─ 03_源码与部署包/
├─ 04_部署文档/
├─ 05_用户操作手册/
├─ 06_API与数据字典/
├─ 07_因子证据与验证报告/
├─ 08_测试与验收报告/
├─ 09_运维服务与SLA/
└─ 10_版本与变更记录/
```

---

## 二、各目录应包含内容

### 01_商务法务

最少应包含：
- `交付清单确认书.pdf`
- `软件或因子库授权说明.pdf`
- `知识产权归属声明.pdf`
- `第三方依赖与授权边界清单.xlsx`
- `数据来源与使用边界说明.pdf`
- `维护服务承诺与SLA.pdf`

重点说明：
- 要写清客户买到的是“使用权”“部署权”“调用权”还是“源码交付权”。
- 要写清第三方数据、论文公式、外部接口、外部因子来源是否允许客户商用。

### 02_交付范围清单

建议文件：
- `交付总览.xlsx`
- `因子交付清单.xlsx`
- `非交付范围说明.md`

因子交付清单字段建议：
- `factor_id`
- `因子名称`
- `类别`
- `频率`
- `覆盖范围`
- `历史起始时间`
- `本期是否交付`
- `是否可直接查询`
- `是否有真实因子值`
- `是否有真值校验`
- `是否有证书`
- `是否需额外环境`
- `备注`

### 03_源码与部署包

建议内容：
- 源码压缩包
- Docker 镜像或导出包
- `requirements.txt` / `package-lock.json`
- 配置模板文件
- 启动脚本
- 示例 `.env.example`

必须保证：
- 不包含真实密钥
- 不包含客户无权接收的私有数据
- 不包含运行时垃圾目录和本地缓存

### 04_部署文档

建议文件：
- `部署手册.md`
- `环境依赖清单.md`
- `配置说明.md`
- `启动与停止说明.md`
- `升级回滚说明.md`
- `常见问题排查.md`

必须写清：
- 操作系统
- Python/Node 版本
- 端口占用
- 外部依赖服务
- 环境变量
- 首次启动步骤
- 验证服务是否成功启动的方法

### 05_用户操作手册

建议文件：
- `用户操作手册.pdf`
- `首次使用指引.md`
- `常见操作示例.md`

应覆盖：
- 如何查看因子
- 如何搜索和筛选
- 如何查看因子详情
- 如何导出数据
- 如何调用 API
- 常见限制和报错说明

### 06_API与数据字典

建议文件：
- `API文档.md`
- `OpenAPI.json` 或接口说明文档
- `数据字典.xlsx`
- `字段说明.md`

至少应覆盖：
- 接口地址
- 请求方式
- 参数说明
- 返回示例
- 错误码
- 鉴权方式
- 限流规则
- 数据更新时间

### 07_因子证据与验证报告

建议文件：
- `因子定义手册.pdf`
- `因子公式与口径说明.xlsx`
- `真值校验报告.pdf`
- `无前视偏差说明.pdf`
- `核心因子研究报告.pdf`
- `证书或评级结果.xlsx`

核心要求：
- 客户能知道每个核心因子“怎么定义、用什么数据、是否验证过、适合什么场景、不适合什么场景”。

### 08_测试与验收报告

建议文件：
- `测试报告.pdf`
- `验收用例清单.xlsx`
- `验收执行结果.xlsx`
- `性能测试结果.pdf`
- `部署验证记录.pdf`

至少应覆盖：
- 功能测试
- 接口测试
- 部署测试
- 回归测试
- 权限与安全检查
- 性能指标

### 09_运维服务与SLA

建议文件：
- `服务响应机制.md`
- `联系人清单.xlsx`
- `故障分级与响应时效.md`
- `问题提交流程.md`

建议写清：
- 工作日支持时间
- 紧急故障响应时间
- 版本更新频率
- 数据异常处理机制
- 停服通知方式

### 10_版本与变更记录

建议文件：
- `版本说明.md`
- `发布记录.xlsx`
- `变更日志.md`

建议字段：
- `版本号`
- `发布日期`
- `新增内容`
- `修复内容`
- `兼容性影响`
- `是否需要客户配合变更`

## 三、交付首页建议

建议在交付包根目录放一个 `README_客户先看.md`，内容尽量控制在 1 页内，至少包含：

1. 产品名称
2. 本次交付版本号
3. 交付日期
4. 交付范围摘要
5. 部署入口
6. 验收入口
7. 联系人
8. 风险提示

可直接参考：

```text
产品名称：A股因子库
版本号：v1.0.0
交付日期：2026-09-01
本次交付范围：33个可直接查询因子 + 101个元数据因子
部署方式：Python 服务 / Docker
验收方式：按《验收用例清单.xlsx》逐项执行
联系人：项目经理 / 技术负责人 / 运维负责人
注意事项：部分因子需客户另行提供数据授权后启用
```

---

## 四、客户验收最关心的 10 个问题

交付包里必须能回答：

1. 客户到底买到了什么？
2. 哪些因子本期可直接使用？
3. 哪些只是目录或元数据，不是可用数据？
4. 客户能否合法商用？
5. 怎么部署？
6. 怎么验收？
7. 怎么调用？
8. 数据出了问题谁负责？
9. 后续怎么升级？
10. 哪些风险和边界必须提前知道？

---

## 五、建议增加的总控表

建议单独做一个 `客户交付总控表.xlsx`，统一管理以下状态：

- 文档是否齐全
- 法务材料是否齐全
- 因子清单是否冻结
- 接口是否可用
- 测试是否通过
- 部署是否验证
- 证据链是否齐全
- 是否允许客户签收

建议状态值：
- `未开始`
- `准备中`
- `已完成`
- `阻断项`

## 六、当前项目特别建议补充的专项文件

结合本项目现状，正式对客前建议额外补这几份：

1. `本期正式交付因子白名单.xlsx`
2. `非交付因子与原因说明.xlsx`
3. `第三方数据与公式授权边界清单.xlsx`
4. `客户部署前检查单.md`
5. `客户验收执行手册.md`
6. `接口鉴权与权限说明.md`
7. `首批核心因子证书包/`

---

## 七、最终交付标准

只有同时满足以下条件，才建议正式交付：

- 法务材料齐
- 交付范围清
- 部署路径通
- 测试基线稳
- 客户手册全
- 证据链可核
- 运维责任明

如果其中任一项缺失，建议口径调整为：
- `演示版`
- `原型版`
- `试用版`
- `预交付版`

不要直接标注为“正式交付版”。
