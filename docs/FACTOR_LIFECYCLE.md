# 因子生命周期：从设想到上架再到淘汰

> 一份因子的完整一生：它从哪里来（假设）→ 如何出生（实现）→ 如何证明自己（七道验真）→ 如何上岗（策略化与外部仿真）→ 如何服务客户（上架订阅）→ 如何退休与死亡（衰减监控与淘汰）。
>
> 本文档是 AgentMatrix 因子挖掘机的**生命周期宪法**：所有自动化流程（7×24 挖掘循环、面板展示、客户交付）都必须遵守本文的状态机与闸门定义。

---

## 0. 总览：一张图看完整一生

```
                     ┌─────────────────────────────────────────┐
                     │  灵感池：论文 / 研报 / 挖掘 Agent / 人工  │
                     └───────────────────┬─────────────────────┘
                                         │ G0 闸门1：源头登记（必须带出处）
                                         ▼
   ┌──────────────┐   G1 闸门2,3   ┌──────────────┐   G2 闸门4-10   ┌──────────────┐
   │ 0 conceived  │ ─────────────► │ 1 implemented │ ─────────────► │ 2 validated  │
   │   （设想）    │  计算正确性     │   （出生）     │   七道验真      │  （成年）     │
   │              │   源库健康      │              │                │              │
   └──────────────┘                └──────────────┘                └──────┬───────┘
        ▲                                 │  任一闸门失败                  │ G3 闸门11,12
        │                                 ▼                              ▼
        │                          ┌──────────────┐   策略复验+外部仿真  ┌──────────────┐
        │   淘汰原因回注              │ 9 rejected   │ ◄──────────────── │ 3 strategy_  │
        └────────────────────────── │   （淘汰）    │    复验失败        │   candidate  │
              挖掘 prompt            └──────────────┘                   └──────┬───────┘
                                                                          │ G4 闸门13
                                                                          ▼
   ┌──────────────┐    衰减监控     ┌──────────────┐    证书过期/失效    ┌──────────────┐
   │ 8 retired    │ ◄───────────── │ 6 published  │ ◄──────────────── │ 4 live_ready │
   │  （退休）     │                │  （上架）     │    人工批准         │  （准live）   │
   └──────────────┘                └──────────────┘                   └──────────────┘
```

**核心原则：只能向前走，不能跳级。** 每一次状态跃迁都由一道闸门守卫，闸门失败的因子进入 `rejected`，其失败原因回注挖掘循环（已验证：2 轮反馈使 PASS 率 70%→100%）。

## 1. 阶段详解

### 阶段 G0 · 设想（conceived）—— 灵感到假设

**因子人生起点不是代码，是一条可追溯的假设。**

| | 内容 |
|---|---|
| 来源 | 论文（如 WorldQuant《101 Formulaic Alphas》）、券商研报、挖掘 Agent 的 LLM 生成、人工洞察 |
| 登记物 | `factor_hypothesis` 记录：假设陈述 + 出处（论文 DOI / 研报页码 / agent prompt 版本）+ 预期方向 + 经济学逻辑 |
| **闸门 1：源头登记** | 无出处的假设**不入队**。哪怕来源是 LLM，也必须记录 prompt 与模型版本 |

**本仓库对应物**：feeder skill（把论文/研报规范化为 `alpha_resource.md`）。
**当前缺口**：无常驻论文/研报监控（arXiv RSS、研报目录）——7×24 挖掘机的第一块待补拼图。

### 阶段 G1 · 出生（implemented）—— 假设变成可计算的代码

| | 内容 |
|---|---|
| 动作 | 规范化为 `FactorResearchSpec` → 用可复用算子实现表达式（禁止一次性 ad hoc 脚本） |
| 测试床 | mock 数据（30 股 × 300 天，seed=42，可复现） |
| **闸门 2：计算正确性** | 公式实现与来源定义**逐项一致**；mock 基准对照 max_abs_diff≈0（独立 benchmark 交叉验证） |
| **闸门 3：源库健康** | 表达式无损坏、无重复定义、参数完整。真实反例：GTJA157 括号损坏、GTJA084 与 059 重复定义、Alpha002 Rank 缺参——这三个因子死在出生台 |

**本仓库对应物**：`research_core/factor_lab`（spec 体系）、zoo_ops_shim 表达式引擎。
**已达标**：1005/1007 因子通过；max_diff=0；可复跑确定性验证通过。
**注意**：mock 通过 ≠ 因子有效。mock 只证明"代码算得对"，不证明"因子在真实市场里有 alpha"。出生不等于成年。

### 阶段 G2 · 成年（validated）—— 七道验真，一生中最严酷的考验

用**真实数据**（amazingdata / Quant API / Qlib）在真实股票池上跑因子值，然后过七道闸门：

| # | 闸门 | 标准 | 防的是什么 |
|---|---|---|---|
| 4 | 数据质量 | 点时序数据、无前视、无幸存者偏差、字段完整、覆盖达标 | 数据泄漏（回测神话的第一来源） |
| 5 | IC 稳定性 | ICIR>0.30 且 bootstrap 置信区间不含 0 | 均值好看但方差巨大的"彩票因子" |
| 6 | 样本外留存 | OOS 留存 ≥70%（IS alpha 折损不超三成） | **过拟合**（samzhang8 教训：91/93 策略死于此） |
| 7 | 成本韧性 | 扣 30bp 交易成本后 alpha 不归零 | 纸面赚钱、实盘亏钱的换手陷阱 |
| 8 | 风格中性 | 市值/行业中性化后 alpha 仍显著 | 因子只是 beta 的化身 |
| 9 | 市场分段 | ≥3 个市场周期方向一致 | 牛市因子/熊市因子的幸存片段 |
| 10 | 冗余去重 | 与已入库因子相关性 <0.7 | 旧因子换马甲（Zoo 库 1040 个里大量这种） |

**本仓库对应物**：`research_core/daily_automation/miner.py`（现有 3 道：IC/ICIR/去重）。
**当前缺口**：7 道中 4 道未实施（bootstrap、OOS、成本、中性化、分段）。
**诚实现状**：过完七道验真的因子数量为 **0**。33 个 QAPI33 因子有真数据在排队等待。

### 阶段 G3 · 准上岗（strategy_candidate）—— 从因子到策略

| | 内容 |
|---|---|
| 动作 | strategy_engine 用**与验真完全相同的因子信号路径**构建目标权重 |
| **闸门 11：策略复验** | OOS 组合年化 > 门槛、最大回撤、换手率达标——单因子好 ≠ 组合好 |
| **闸门 12：外部仿真** | backtest_adapter 打包给 GM/PTrade/QMT 外部引擎，**终端回测证据返回并解析通过** |

**本仓库对应物**：`research_core/strategy_engine` + `research_core/backtest_adapter`（管线已存在，复验标准待统一）。
**红线**（alpha-pipeline 规则）：内部验证是必要不充分条件；**没有外部仿真证据 + 显式人工批准，永远不得 promote 到 live_ready**。

### 阶段 G4 · 上岗（live_ready → published）—— 服务客户

| | 内容 |
|---|---|
| **闸门 13：人工批准** | 显式 human approval（一个人类在证据链上签字），写入 Supabase 因子字典/信号表 |
| 上架物 | 白名单（只含过闸因子）+ 每因子一张**验证证书** |
| 证书内容 | 过了哪几道闸门、IC/ICIR 数值、OOS 留存、数据源、验证时间、代码 commit、负责人 |

**客户看到的世界**：没有分级、没有灰区——只有"带证书的因子"。证书即信任，就像食品溯源码：客户不需要理解车间质检流程，只需要扫到那张证书。

### 阶段 · 退休与死亡

上架不是终点。**因子会衰减**（alpha decay 是量化的自然规律）：

| 状态 | 触发 | 动作 |
|---|---|---|
| 衰减预警 | 滚动窗口 IC 跌破阈值 / 换手异常升高 | 面板标红，进入观察期 |
| **8 retired（退休）** | 预警后持续恶化，人工确认 | 摘牌下架，**历史证据链完整保留**（供归因与复盘） |
| **9 rejected（死亡）** | 任一闸门失败 | 记录淘汰原因（哪道闸、什么数值），**回注挖掘 prompt** 让挖掘机学会不再生同样的因子 |

## 2. 一生中的证据链（审计追踪）

每个状态跃迁产生一条不可篡改的证据记录：

```json
{
  "factor_id": "QAPI33:roe_ttm",
  "transition": "implemented -> validated",
  "gate": "G2-6 OOS retention",
  "evidence": {
    "is_ic": 0.062, "oos_ic": 0.055, "retention": 0.887,
    "data_source": "amazingdata", "universe": "csi800",
    "window": ["2019-01-01", "2025-12-31"],
    "code_commit": "a1b2c3d", "runner_version": "miner.py v2.1",
    "timestamp": "2026-08-30T10:00:00Z"
  },
  "approved_by": "human:zhang / auto:agent"
}
```

规则：**无证据记录的状态变更视为非法变更**。7×24 机器产出的所有东西必须可追溯到"谁、用什么数据、什么代码、何时"。

## 3. 状态机对照表（本仓库落地情况）

| 状态 | 生命周期语义 | 仓库对应 | 落地情况 |
|---|---|---|---|
| 0 conceived | 设想（假设已登记） | factor_hypothesis（待建） | ⚠️ 待建 |
| 1 implemented | 出生（代码可算、mock 通过） | factor_lab spec + zoo mock | ✅ 1005 因子 |
| 2 validated | 成年（七道验真通过） | miner.py gates | ❌ 缺 4 道闸门，现有 A 级 = 0 |
| 3 strategy_candidate | 准上岗（组合验证+外部仿真） | strategy_engine / backtest_adapter | ⚠️ 管线在，标准待统一 |
| 4 live_ready | 通过人工批准 | Supabase + human approval | ⚠️ 待建白名单/证书导出 |
| 6 published | 上架（客户可见可订阅） | factor-db 客户面板 | ⚠️ 待从研究面板分离 |
| 8 retired | 退休（衰减摘牌，证据保留） | 衰减监控（待建） | ❌ 待建 |
| 9 rejected | 死亡（闸门淘汰，原因回注） | Tier D + mining_bridge 反馈 | ✅ 已验证闭环（70%→100%） |

> 补充：`truth-proofed`（官方真值对照通过，如 Alpha101 vs 论文原值）作为 `implemented` 的加强认证存在，记为 S 级证据。

## 4. 三条铁律

1. **闸门只能拦，不能放水。** 指标差一点就是差一点——闸门存在的意义就是让"看起来不错"的因子死在里面。
2. **淘汰是营养，不是损失。** 每个 rejected 因子的死因都让挖掘机下一代更聪明。没有死亡记录的挖掘机在原地打转。
3. **上架即承诺。** 客户看到的每个因子都背着一张可复核的验证证书。证书上的数字，任何人任何时候重跑都应得出相同结论（可复现性是信任的底座）。
