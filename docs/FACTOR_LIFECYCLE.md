# 因子生命周期：从设想到上架再到淘汰（v2.0）

> 一份因子的完整一生：它从哪里来（假设）→ 如何出生（实现）→ 如何证明自己（九道验真）→ 如何上岗（策略化与外部仿真）→ 如何服务客户（上架订阅）→ 如何退休与死亡（衰减监控与淘汰）。
>
> 本文档是 AgentMatrix 因子挖掘机的**生命周期宪法**：所有自动化流程（7×24 挖掘循环、面板展示、客户交付）都必须遵守本文的状态机与闸门定义。

**版本 v2.0 · 2026-08-30**（合并 Opus 5 修订版 + 本仓库三处修正）

v2.0 相对 v1.0 的关键变更（每条都是「不改就不能卖」级）：

| `5 suspended` | `6 published` | 重验 | 重跑九道验真全过，签发新证书 | human |
| `5 suspended` | `8 retired` | 重验失败，或挂起满 30 天未重验 | — | auto |
| `6 published` | `7 deprecated` | 出现更优替代（相关性 >0.7 且 ICIR 高出 ≥20%） | — | human |
| `7 deprecated` | `8 retired` | 客户迁移期满 90 天 | — | auto |
| 任意状态 | `9 rejected` | 任一闸门失败 | — | auto |

**合法跃迁仅限上表 13 条。任何不在表内的状态变更，CI 直接拒绝。**

**核心原则（v2.0 修订）**：**前进必须逐级过闸，不得跳级；暂停、降级与淘汰可从任意状态即时发生。**

**「失败回注」的准确含义**：`rejected` 是**终态**，因子本身不复活。回注的是**死因**（哪道闸、什么数值、什么形态），写入挖掘 prompt；挖掘机据此产出的新因子取**新的 factor_id**，从 `conceived` 重新开始。**同一 factor_id 不得二次进入流程。**

> ⚠️ **「2 轮反馈使 PASS 率 70%→100%」的正确读法**
>
> 该数字来自 **G1（计算正确性 / 源库健康）**，属**确定性校验**——代码算得对不对有唯一答案，100% 通过是正常的工程结果。
>
> **它不是有效性证据，禁止出现在任何客户材料、报价单或路演材料中。**
>
> G2 九道验真的**目标 PASS 率分层设定**（本仓库修正 B）：
> - `novel`（挖掘机新生因子）：3—8%；若 >15%，判定为**闸门对挖掘机过拟合**，正确处理是提高门槛，不是庆祝
> - `replication`（复现已发表因子）：允许 20—30%——第三方已发表的因子本身经过筛选，合法通过率可以更高，闸门未必有问题

## 1. 阶段详解

### 阶段 G0 · 设想（conceived）—— 灵感到假设

**因子人生起点不是代码，是一条可追溯的假设。**

| | 内容 |
|---|---|
| 来源 | 论文（如 WorldQuant《101 Formulaic Alphas》）、券商研报、挖掘 Agent 的 LLM 生成、人工洞察 |
| 登记物 | `factor_hypothesis` 记录：假设陈述 + 出处（论文 DOI / 研报页码 / agent prompt 版本 + 模型版本 + 温度参数）+ 预期方向 + 经济学逻辑 + **`source_class`** |
| **闸门 1：源头登记** | 四项齐备才入队：① 假设陈述 ② 出处 ③ 预期方向（正 / 负）④ **经济学逻辑一句话**。缺任一项直接 `9 rejected`，不进入 `conceived` |
| **方向锁定（v2.0 新增）** | 预期方向在此刻锁死。**事后因为 IC 为负就翻转符号 = 一次未申报的样本内试验**，必须计入闸门7 的试验次数 N |
| **`source_class`（本仓库修正 B）** | `novel`（挖掘机原创）或 `replication`（复现已发表因子）。该字段决定闸门8 的 OOS 基线与 G2 PASS 率阈值分层 |

**本仓库对应物**：feeder skill（把论文/研报规范化为 `alpha_resource.md`）。
**当前缺口**：无常驻论文/研报监控（arXiv RSS、研报目录）——7×24 挖掘机的第一块待补拼图。

### 阶段 G1 · 出生（implemented）—— 假设变成可计算的代码

| | 内容 |
|---|---|
| 动作 | 规范化为 `FactorResearchSpec` → 用可复用算子实现表达式（禁止一次性 ad hoc 脚本） |
| 测试床 | mock 数据（30 股 × 300 天，seed=42，可复现） |
| **闸门 2：计算正确性** | 公式实现与来源定义**逐项一致**；mock 基准对照 max_abs_diff≈0（独立 benchmark 交叉验证） |
| **闸门 3：源库健康** | 表达式无损坏、无重复定义、参数完整。真实反例：GTJA157 括号损坏、ALPHA002 Rank 缺参数 |

**本仓库对应物**：`research_core/factor_lab`（spec 体系）、zoo_ops_shim 表达式引擎。
**已达标**：mock 全量可复跑、确定性验证与 NaN 鲁棒性 PASS、benchmark max_diff=0。

> **⚠️ 计数口径（本仓库修正 A，引用必须带字段名）**
>
> zoo mock 运行的两个口径**不矛盾**，引用时必须写明用哪一个（数据源 `runtime/zoo_mock/out/report.json`）：
> - **运行失败 `n_fail = 2/1007`**：GTJA157（表达式语法损坏）、ALPHA002（Rank 缺参数）——真正跑不过的
> - **源库缺陷标记 `zoo_defects`（清单若干条）**：GTJA084/059 重复定义（两个都能跑，二选一保留）、一元负号缺算子（shim 已修复）、纯标量中间值等——**是标记不是失败**
>
> 一句话：**「运行失败 2 个」数的是求值器拒绝的；「缺陷标记」数的是源库质量问题。** 在 miner 重跑核对前，两个数字都不得单独引用到任何客户材料。

**注意**：mock 通过 ≠ 因子有效。mock 只证明"代码算得对"，不证明"因子在真实市场里有 alpha"。出生不等于成年。

### 阶段 G2 · 成年（validated）—— 九道验真，一生中最严酷的考验

用**真实数据**在真实股票池上跑因子值，然后过九道闸门。**九道全过才算 validated，缺一不可，不设「部分通过」。**

**数据口径前置约定**（三个数据源必须先对齐，否则闸门4 无意义）：

| 项 | 强制规则 |
|---|---|
| 数据源 | amazingdata / Quant API / Qlib 三选一；**同一因子的 IS 与 OOS 必须同源**，跨源结果不可拼接 |
| 复权 | 统一后复权；因子值与收益率使用同一复权口径 |
| 财报对齐 | **一律使用 announcement date（公告日），禁止 report date（报告期）**——用报告期即构成前视偏差 |
| 停牌填充 | 停牌日因子值置 NaN，**不做前向填充** |
| 股票池 | **PIT 历史成分**（含调入调出、退市、ST 变更），不得用当前成分回溯 |

**闸门执行顺序（本仓库修正 C，强制条款）**：

> 九道闸门**按 4→5→6→7→8→9→10→11→12 的固定顺序执行，逐道短路**（先失败先出局，不再跑后面的闸门）。**闸门5 的可执行性过滤会改变股票池，其后所有闸门（6—12）的统计量一律在过滤后的全集上计算**，否则各实现口径漂移、结果不可比。同一因子重验时顺序不变。

| # | 闸门 | 标准（可执行） | 防的是什么 |
|---|---|---|---|
| 4 | 数据质量 | 点时序数据、无前视、无幸存者偏差；字段缺失率 <5%；覆盖股票数 ≥ 池内 90% | 数据泄漏（回测神话的第一来源） |
| **5** | **可执行性（v2.0 新增）** | 信号日涨停不可买、跌停不可卖；停牌剔除，复牌首日不参与；ST/\*ST 按 PIT 状态剔除；上市 <120 日剔除；过去 20 日均成交额 <¥2,000 万剔除。**过滤前后 alpha 衰减 >50% 直接判死** | **买不到的收益**——A 股回测与实盘之间最大的裂缝 |
| 6 | IC 稳定性 | **月频 Rank IC（Spearman）**，滚动 36 个月：ICIR > 0.30，且 bootstrap（1000 次，block size = 6）95% 置信区间不含 0 | 均值好看但方差巨大的"彩票因子" |
| **7** | **多重检验校正（v2.0 新增）** | 按本轮实际试验次数 N 计算 **Deflated Sharpe Ratio > 0**，或 Benjamini-Hochberg FDR 控制 q ≤ 0.05。**N 必须写进证书**（含参数网格搜索次数与符号翻转次数） | **大规模抽奖**——1005 个因子过单因子阈值，纯噪声也会批量通过 |
| 8 | 样本外留存 | OOS 留存 ≥70%。**按 `source_class` 分层**（本仓库修正 B）：`novel` 切分点必须在因子实现前写进 factor_hypothesis 并锁定；最近 12 个月为**全局封存 holdout**，仅在闸门15 前开封一次；**同一 factor_id 访问 OOS 上限 3 次，超限自动 rejected**。`replication` 的 OOS 基线 = max(论文数据窗口终点, 入库预注册日) 之后——复现类因子无法对文献"装作没看见"，诚实基线是**发表后样本外**（post-publication OOS） | **过拟合**（samzhang8 教训：91/93 策略死于此） |
| 9 | 成本韧性 | 报告 **breakeven cost（alpha 归零时的单边成本 bp）**，要求 ≥ 实际成本的 **2 倍**。实际成本＝印花税 5bp（卖出单边）+ 佣金 2.5bp 双边 + 冲击成本（按日均成交额分档）。**必须同时报出年化双边换手率** | 纸面赚钱、实盘亏钱的换手陷阱 |
| 10 | 风格中性 | 对市值、行业，以及 Barra 五因子（Beta / 动量 / 波动 / 流动性 / 估值）回归取残差后，残差 IC 仍满足闸门6 | 因子只是 beta 的化身 |
| 11 | 市场分段 | **切分规则事前固定**（按自然年，不按事后识别的牛熊）：≥3 个完整自然年方向一致，且**最差年份 IC ≥ 全样本 IC 的 30%** | 牛市/熊市因子的幸存片段；以及「事后划分周期」这种数据窥探 |
| 12 | 冗余去重 | 两两相关性 <0.7 **且**对已入库因子正交化后，**残差 IC 仍达闸门6 标准的 70%**（增量 IC 检验） | 旧因子换马甲；以及两两不相关、整体却高度共线的因子群 |

**本仓库对应物**：`research_core/daily_automation/miner.py`。

### 阶段 G3 · 准上岗（strategy_candidate）—— 从因子到策略

| | 内容 |
|---|---|
| 动作 | strategy_engine 用**与验真完全相同的因子信号路径**构建目标权重 |
| **闸门 13：策略复验** | 全部为 **OOS 口径**，三条同时满足：① 年化超额收益（对 csi800）**≥ 8%** ② 最大回撤 **≤ 20%** ③ 年化双边换手 **≤ 12 倍**；另需报告 OOS 夏普 **≥ 1.0**。单因子好 ≠ 组合好 |
| **闸门 14：外部仿真** | backtest_adapter 打包给 GM/PTrade/QMT 外部引擎，**终端回测证据返回并解析通过**；外部引擎与内部回测年化**偏差 >3 个百分点即判失败**并排查 |
| **闸门 14b：容量测算（v2.0 新增）** | 在 ¥1,000万 / ¥5,000万 / ¥2亿 三档资金规模下分别回测，记录 alpha 衰减曲线，得出**容量上限**＝ alpha 衰减 ≤30% 的最大规模。该数字直接进证书 |

**本仓库对应物**：`research_core/strategy_engine` + `research_core/backtest_adapter`（管线已存在，**v2.0 已给出数字门槛，待落码**）。

**红线**（alpha-pipeline 规则）：内部验证是必要不充分条件；**没有外部仿真证据 + 显式人工批准，永远不得 promote 到 live_ready**。

### 阶段 G4 / G5 · 上岗（strategy_candidate → live_ready → published）—— 服务客户

v1.0 的「人工批准」同时出现在正文闸门和总览图两处，已拆成两道，各管一段：

| | 内容 |
|---|---|
| **G4 · 闸门15：人工批准** | 管 `strategy_candidate → live_ready`。显式 human approval（一个人类在证据链上署真名签字），写入 Supabase 因子字典 / 信号表。**这是全流程唯一强制人工点** |
| **G5 · 闸门16：证书签发** | 管 `live_ready → published`。证书 12 个字段全部齐备则自动签发；**缺任一字段不得上架** |
| 上架物 | 白名单（只含过闸因子）+ 每因子一张**验证证书** |

**客户看到的世界**：没有分级、没有灰区——只有"带证书的因子"。证书即信任，就像食品溯源码：客户不需要理解车间质检流程，只需要扫到那张证书。

#### 验证证书 · 12 个必填字段（客户可见，可直接作为报价附件）

| # | 字段 | 说明 |
|---|---|---|
| 1 | factor_id / 名称 / 一句话经济学逻辑 | — |
| 2 | 通过的闸门清单 | 闸门 4—16 逐项打勾 |
| 3 | 月频 Rank IC / ICIR | 含 bootstrap 95% 置信区间 |
| 4 | OOS 留存率 **+ IS/OOS 切分日期** | 切分日期必须是预注册值（replication 类为发表后基线） |
| 5 | **试验次数 N + Deflated Sharpe** | 没有 N，IC 数字没有意义 |
| 6 | **容量上限（capacity）** | alpha 衰减 ≤30% 的最大资金规模 |
| 7 | **breakeven cost + 年化双边换手** | — |
| 8 | 数据源 / 股票池 / 回测窗口 | 含 PIT 与 announcement date 声明 |
| 9 | 代码 commit + runner 版本 | 可复现性锚点 |
| 10 | 验证时间 **+ 证书有效期** | **有效期 6 个月**，到期自动转 `5 suspended` |
| 11 | 负责人（署真名） | — |
| 12 | **摘牌 SLA** | 见下 |

**摘牌 SLA（写入订阅合同）**：

- 进入 `5 suspended`：**24 小时内**邮件 + 面板通知全部订阅客户，说明触发原因与预计重验完成时间
- 进入 `7 deprecated`：提供 **90 天迁移期**，期间因子仍可用，并同时给出推荐替代因子
- 进入 `8 retired`：**提前 30 天**通知；若当年摘牌因子数超过订阅包总数的 **20%**，按未服务月份比例**退费**
- 历史证据链在任何状态下**永久保留**，客户可随时复核已交付信号在当时的依据

### 阶段 · 暂停、降级、退休与死亡

上架不是终点。**因子会衰减**（alpha decay 是量化的自然规律，且随使用者增多而加速）。触发条件全部量化：

| 状态 | 量化触发条件 | 动作 |
|---|---|---|
| 衰减预警（不改状态） | 滚动 12 个月 Rank IC **< 上架时 IC 的 50%**，且连续 **2 个月** | 面板标红，进入 60 天观察期，**暂不通知客户** |
| **5 suspended（暂停）** | ① 观察期内未回升 ② 或滚动 12 个月 ICIR **< 0.15** ③ 或证书到期未重验 ④ 或数据源中断 >5 交易日 | 停止对外分发信号，**24h 内通知客户**；30 天内必须重验，否则自动 retired |
| **7 deprecated（降级）** | 出现替代因子：与本因子相关性 **>0.7** 且 ICIR **高出 ≥20%** | 保留分发，标注「已有更优替代」，给客户 **90 天迁移期** |
| **8 retired（退休）** | suspended 重验失败 / 挂起超 30 天 / deprecated 迁移期满 | 摘牌下架，**历史证据链完整保留**（供归因与复盘） |
| **9 rejected（死亡）** | 任一闸门失败 | 记录死因（哪道闸、什么数值、什么形态），**回注挖掘 prompt**。因子本身**不复活**，新因子取新 factor_id |

**上架集合规模纪律（隐含条款，写成明文）**：证书有效期 6 个月 × 九道闸门全量重验意味着**每个上架因子每年消耗 2 次完整验真**。上架集合必须小而精——**任何「面板因子数量」类 KPI 不得成为放宽闸门的理由**。

## 2. 一生中的证据链（审计追踪）

每个状态跃迁产生一条不可篡改的证据记录：

```json
{
  "factor_id": "QAPI33:roe_ttm",
  "source_class": "novel",
  "transition": "implemented -> validated",
  "gate": "G2-8 OOS retention",
  "evidence": {
    "is_ic": 0.062, "oos_ic": 0.055, "retention": 0.887,
    "data_source": "amazingdata", "universe": "csi800",
    "window": ["2019-01-01", "2025-12-31"],
    "oos_access_count": 1,
    "code_commit": "a1b2c3d", "runner_version": "miner.py v2.1",
    "timestamp": "2026-08-30T10:00:00Z"
  },
  "approved_by": "human:zhang / auto:agent"
}
```

规则：

- **无证据记录的状态变更视为非法变更**。7×24 机器产出的所有东西必须可追溯到"谁、用什么数据、什么代码、何时"
- **OOS 访问计数器是证据链的一部分**：每次开封封存 holdout 必须留记录，第 4 次访问自动 `rejected`
- **同一 factor_id 不得二次进入流程**（rejected 后重生的新因子取新 id）

## 4. 三条铁律（v2.0 修订）

1. **闸门只能拦，不能放水。** 指标差一点就是差一点——闸门存在的意义就是让"看起来不错"的因子死在里面。G2 PASS 率异常高时正确动作是怀疑闸门，不是庆祝。
2. **淘汰是营养，不是损失。** 每个 rejected 因子的死因都让挖掘机下一代更聪明。没有死亡记录的挖掘机在原地打转。rejected 是终态——回注的是死因，不是因子本身。
3. **上架即承诺。** 客户看到的每个因子都背着一张 12 字段、含有效期与摘牌 SLA 的验证证书。证书上的数字，任何人任何时候重跑都应得出相同结论（可复现性是信任的底座）。**没有第一个证书之前，对外不得暗示有货。**
