# AGE-8 每日更新 + 持续因子挖掘系统 — 设计方案与 v1 实现说明

> AgentMatrixLab · CEO Jarvis · 2026-08-12 · 对应 GitHub issue AGE-8
> 关联里程碑：M1（数据接入与存储）、M2（回测与评估台）、M3（多策略 Alpha 流水线）

## 1. 背景与目标

董事会要求：**建立一个每天更新、每天根据新的信息不断挖掘因子的系统**。

拆解为两个持续运行的闭环：

1. **每日更新闭环**：每天自动拉取最新行情 → 校验质量 → 落入统一存储 → 供下游使用。
2. **因子挖掘闭环**：每天基于"新到信息"评估候选因子 → 通过门槛（IC/ICIR/相关性）→ 注册入库 → 沉淀为策略资产。

系统必须满足三条硬约束：

- **可验证**：每天产出可审计的日志与报告（谁、什么时间、拉了什么、算出什么）。
- **防过拟合**：挖掘结果必须过统计门槛（IC/ICIR/相关性去重），禁止裸跑裸存。
- **可演进**：数据源、股票池、候选因子集、评估门槛都是可替换的配置，不是硬编码。

## 3. 模块 ① 每日数据更新（对应 M1）

| 项 | v1 实现 | 生产化路径（Ada） |
|----|---------|------------------|
| 股票池 | CSI300 成分股（csindex 接口，2026-08-11 验证可用，300 只） | 全A 股票池 + 退市股（消除存活偏差） |
| 行情源 | Tencent 日线（`stock_zh_a_hist_tx`，qfq；东财逐股接口在本机被限流，已验证腾讯可用） | SmartData ClickHouse (115.159.73.134) + 分钟线 |
| 存储 | 本地 DuckDB `daily_kline(code,date,open,high,low,close,volume,amount)`，主键 (code,date) 幂等 upsert | ClickHouse 生产库 + parquet 快照 |
| 质量校验 | 行数/覆盖率/最新交易日/缺失股票清单 | 更严格：复权一致性、停牌处理、异常值检测 |
| 增量更新 | 每天全窗口刷新（幂等） | 只拉增量 + 断点续传 |

**数据可用性验证（2026-08-12 实跑）**：CSI300 成分股接口 0.3s 返回 300 只；腾讯日线单股 ~0.4s，60 日窗口全量 300 只约 3-5 分钟。

## 4. 模块 ② 持续因子挖掘（对应 M3）

**挖掘循环（每天触发一次）**：

1. 取最新数据窗口（默认 90 自然日）的 panel；
2. 计算当日未来收益（next day return）；
3. 计算候选因子值（v1: Alpha158 前 20 个价格/成交量技术因子，复用 `alpha158_lab/factors/compute.py`）；
4. 对每个因子跑完整评估套件（复用 `factor_lab/evaluation.evaluate_factor`：Rank IC、ICIR、换手率）；
5. **门槛判定**：`|Rank IC| ≥ 0.03` 且 `ICIR ≥ 0.30` 且评估状态非 fail；
6. **去重判定**：与已注册因子的平均截面秩相关 `corr_max < 0.70`；
7. 通过者写入 `runtime/factor_registry.json`（记录 IC/ICIR/换手/corr/入库时间）；
8. 全部结果写入 `runtime/daily_mining_log.jsonl`（可审计）。

**门槛依据**（factor-investing-methodology）：IC_IR > 0.5 判定为"可能有效"是投研级标准；v1 用 ICIR≥0.30 作为日常监控线，新因子入库后再由 M2 评估台做正式样本外验证。

**候选因子的"新信息"维度（v1 → v3 演进）**：

| 版本 | 新信息来源 | 说明 |
|------|-----------|------|
| v1（本次） | 新的行情数据 | 每天窗口滑动，因子 IC/ICIR 用最新数据重估 |
| v2（Ada） | 财报/事件/行业数据 | 基本面因子、事件驱动因子 |
| v3（Ada） | 新闻/舆情/另类数据 | qlib_lab AIFactorMiner（LLM 生成表达式）+ 新闻情绪 |

## 5. 模块 ③ 调度、报告与监控

- **调度**：本机 crontab 每日 18:30 (Asia/Shanghai，收盘后) 执行 `run_daily`；日志重定向到 `runtime/daily_automation/cron.log`。
- **报告**：`data/daily_store/reports/YYYY-MM-DD.md`（数据更新摘要 + 质量检查 + 挖掘结果表 + 新注册因子 + 下一步），`latest.md` 指向最新。
- **失败处理**：数据源失败不阻塞（记录 failed 数）；数据量不足时挖掘自动跳过并说明原因；退出码非 0 时 cron 邮件/飞书告警（v2）。
- **演进监控（v2）**：因子 IC 衰减监控——已注册因子在滚动窗口的 IC 趋势，衰减超阈值自动降级。

## 6. 治理与防过拟合

- 注册入库 ≠ 实盘可用：入库因子必须再经 M2 评估台（样本外、成本韧性、FDR）才进入策略组合。
- 门槛恒定：IC/ICIR/corr 阈值是配置，不随结果调整（防止 p-hacking）。
- 全审计：每次运行的输入窗口、候选集、评估结果全部落 JSONL，可回放。
- 相关性去重：新因子与已注册因子 corr ≥ 0.70 直接拒绝，控制因子动物园规模。

## 7. 与现有资产的关系

- 复用：`alpha158_lab`（因子计算）、`factor_lab/evaluation`（评估套件）、`contracts`（数据契约）、`common/paths`（路径约定）。
- 新增：`research_core/daily_automation/`（store/fetcher/miner/report/run_daily）。
- 生产化衔接：`DailyStore` 是存储接口缝，M1 落地 ClickHouse 后替换后端不影响上层；`factor_registry.json` 是 M3 策略组合的输入。
- 与 115 服务器 ClickHouse（SmartData）的关系：v1 不依赖远程服务（本机自包含）；接入后股票池/频率升级，接口不变。
