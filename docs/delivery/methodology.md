## 2. 数据、基准与口径

- **行情面板**：RQData FULL 的 A 股全市场日线，由 Hermes 在 115 服务器导出为离线 Parquet，本地读取器不联网。面板的列名与类型契约见 `docs/delivery/runbook_hermes.md` 第 2 节（与 `data_contract_rqdata_panel.md` 的原始导出契约不同，中间需要一层明确映射）。
- **因子值**：可来自两条通道，二选一：
  1. **流水线内置 transform**（当前只有 `negative_pct_change` 与 `rolling_mean` / `rolling_mean_log`）；
  2. **Hermes 导出的预计算因子值**长表 Parquet（`date, code, factor_name, value` + sidecar），用于 ROC、RSI6、alpha002 等流水线算不了的因子。
  **两条通道必须给出完全一致的 `result_hash`**（同一份数据、同一因子），这是等价性的验收条件。
- **复权口径（已按接龙10 裁定）**：**流水线的收益与价格均使用后复权**（`configs/validation_gates.yaml` 的 `adjust_type: post`）；**原始 OHLC 与复权因子作为审计字段一并导出**。面板 sidecar 必须声明 `price_basis`，读取器会把它写进 `run_manifest.json` 的 `panel_price_basis`，使口径可核查；**代码不做任何自动复权换算**。待办：Hermes 需确认库里已有的因子值是用哪种价格算出来的。
- **基准**：中证全指 `000985` 的独立日收益文件；价格收益或全收益口径必须来自 `run_manifest.json`，不得自行假设。
- **文件校验**：逐文件核对 sidecar 声明的来源、区间、行数与 SHA-256。哈希一致只证明文件字节一致，不单独证明来源真实性。
- **时间切分（已按接龙10 裁定，已冻结）**：train `2020-01-02 ~ 2022-12-31`、OOS `2023-01-01 ~ 2026-08-31`（44 个月，含 2023/2024/2025 三个完整年）。裁定理由：OOS 所需的 2023–2026 因子值已在库、不依赖下载配额；2016–2019 因子值按实测速度需十几小时，会拖到 10/5 之后。**该切分一旦写入 `run_manifest` 即冻结，不再调整**；2016–2019 数据 10/7 之后作稳健性附录。更改记录：`configs/validation_gates.yaml` commit `146c0d7`（只改 `split` 三行，门槛数值与 `adjust_type` 未动）。Hermes 需按此重写 `run_manifest`，作废 `b8d740f6`，并写明「预先声明的方案 B；尚未看过任何 OOS 结果」。

## 3. 验证流程

1. 固定候选清单（`candidate_list.csv` + SHA-256）、代码 commit、面板与因子文件哈希、日期切分与全部运行参数。
2. 读取面板与因子值：每个文件的 SHA-256、列、类型、`(date, code)`（因子文件为 `(date, code, factor_name)`）唯一性、日期区间、行数全部校验；**任何不符直接报错退出**，不填充、不降级。
3. 走既有准入逻辑：上市满 120 天、未退市、非 ST、非停牌、`volume > 0`、价格未触涨跌停。
4. 走既有样本外逻辑：切分、`coverage` / `rank_ic` / `oos_seal` / `style_r2` / `residual_ic` / `cost_adjusted_return` / `dd_vol_ratio` / `parameter_perturbation` 八条门槛，**阈值、判定逻辑、成本设定、切分一律不动**。
5. **选簇代表只看训练段**：`--segment train` 只输出训练期统计量、不评估任何门槛、不计算也不写出任何样本外指标。禁止用 OOS 结果挑选因子或簇代表。
6. **参数扰动按 A+B 处理（已按接龙10 裁定）**：有窗口参数的因子，导出 `<因子ID>` 基准 + `<因子ID>|window=<w>` 的 0.8×、1.2× 变体，且**导出的基准必须与库中值一致，不一致即按 B 处理**；无窗口参数的因子按 B 处理。**B 的含义**：该因子的 `parameter_perturbation` 门槛记为**「无法测量 → 不通过」**，整批继续、不中断、不报错，**绝不判通过**。台账在 `validation_result.json` 里可见：门槛 `actual.measured = false`、`actual.unmeasured_variants` 列出缺的名字、阈值 `unmeasured_counts_as = "not_passed"`。
7. **风险暴露处理（已按接龙10 裁定）**：`candidate_list.csv` 中 `risk_exposure=true` 的因子照常跑完全流程并出具状态与指标，但**不计入有效 Alpha 计数**（`validated_effective_alpha`）**也不进入交付包**；清单与打包器都会把它单独列出并写明原因。
8. 批量运行：一条命令跑完全部候选；单因子失败记录原因后继续，不中断整批。因子多、单因子耗时长时可按因子分片并行（每片独立输出），再用 `scripts/merge_batch_manifests.py` 合并；**合并前会校验各片的 commit、面板/因子文件/配置哈希与切分完全一致，不一致直接拒绝合并**，且合并只拼接结论、不重算判定。
9. 结果核对：候选、面板/因子文件哈希、切分、参数、门槛结果、输出哈希必须相互一致；写 `run_manifest.json` / `batch_manifest.json`。
9. 打包：**只有 `status == "validated"` 的因子进入交付包**；淘汰、报错、`needs_human`、未运行的因子只列状态与原因。一个都没通过时打包脚本以非零退出码结束并给出 warning，避免误发空包。

本阶段不新增因子，不用合成数据、fixture、mock、样本内表现或单元测试结果替代真实数据证据。所有 `test_only` 夹具只用于验证代码行为。

## 4. 结果口径

- 每个交付因子关联：稳定 ID、名称、公式/计算口径、所需字段、方向、验证状态、失败门槛与原因、`result_hash`、证据文件路径 —— 由 `factor_catalog.csv` 承载。
- 实际通过数量、指标、覆盖区间与文件哈希**全部从正式运行的产物填入**，本文与目录脚本都不会预填、不会估算。
- 研究检验只描述历史样本上的计算结果，不保证未来表现、收益水平或风险水平。任何收益、夏普、回撤或容量描述都必须有可复核报告支持，不得解释为承诺。
